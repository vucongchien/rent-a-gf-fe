### US-001: Xem Dashboard Tổng Quan

**As a** Admin, **I want** xem tổng quan sức khỏe nền tảng trên Dashboard, **so that** tôi nắm được tình trạng hoạt động hiện tại mà không cần tra cứu từng mục riêng lẻ.

**Priority:** Must Have

#### Acceptance Criteria

| AC ID | Scenario | Given | When | Then |
|-------|----------|-------|------|------|
| AC-001-01 | Happy path — xem Dashboard đầy đủ | Admin đã đăng nhập, dữ liệu nền tảng tồn tại | Admin truy cập trang Dashboard | Hiển thị các chỉ số KPI: số đặt lịch mới trong ngày, số người dùng mới, tổng Kanocoin lưu thông; tất cả số liệu là dữ liệu hiện tại từ hệ thống |
| AC-001-02 | Happy path — tự động làm mới | Admin đang ở trang Dashboard | Sau một khoảng thời gian, hệ thống tự kích hoạt làm mới | Các chỉ số KPI trên Dashboard được cập nhật với dữ liệu mới nhất từ hệ thống mà không cần Admin thao tác |
| AC-001-03 | Error — dịch vụ dữ liệu không phản hồi | Admin đăng nhập, nhưng dịch vụ cung cấp số liệu không phản hồi | Admin truy cập trang Dashboard | Hiển thị thông báo "Không thể tải dữ liệu, vui lòng thử lại" ở vị trí từng chỉ số; trang không bị trắng hoàn toàn |
| AC-001-04 | Edge — không có dữ liệu trong ngày | Admin đăng nhập vào ngày đầu tiên hệ thống hoạt động, chưa có giao dịch nào | Admin xem Dashboard | Tất cả chỉ số KPI hiển thị giá trị 0 (không hiển thị lỗi hoặc ô trống) |

### US-002: Xem Danh Sách Companion

**As a** Admin, **I want** xem và lọc danh sách Companion, **so that** tôi nhanh chóng tìm được Companion cần xử lý theo từng trạng thái.

**Priority:** Must Have

#### Acceptance Criteria

| AC ID | Scenario | Given | When | Then |
|-------|----------|-------|------|------|
| AC-002-01 | Happy path — xem danh sách | Admin đăng nhập | Admin truy cập trang Quản lý Companion | Hiển thị danh sách Companion phân trang, mỗi dòng gồm: tên, ảnh đại diện, trạng thái, ngày đăng ký |
| AC-002-02 | Happy path — lọc theo trạng thái | Admin đang ở trang Quản lý Companion | Admin chọn bộ lọc trạng thái "Chờ duyệt" | Chỉ hiển thị các Companion có trạng thái "Chờ duyệt"; số lượng kết quả hiển thị chính xác |
| AC-002-03 | Happy path — tìm kiếm theo tên | Admin đang ở trang Quản lý Companion | Admin nhập tên vào ô tìm kiếm | Danh sách lọc theo tên, kết quả khớp một phần tên cũng được hiển thị |
| AC-002-04 | Edge — danh sách rỗng | Admin lọc theo trạng thái không có Companion nào | Admin áp dụng bộ lọc | Hiển thị thông báo "Không có Companion nào phù hợp với bộ lọc" thay vì bảng trống |
| AC-002-05 | Error — không tải được danh sách | Dịch vụ danh sách không phản hồi | Admin truy cập trang | Hiển thị thông báo lỗi và nút thử lại |

### US-003: Duyệt hoặc Từ Chối Hồ Sơ Companion Mới

**As a** Admin, **I want** duyệt hoặc từ chối hồ sơ Companion mới nộp, **so that** chỉ những Companion đáp ứng tiêu chuẩn mới được hoạt động trên nền tảng.

**Priority:** Must Have

#### Acceptance Criteria

| AC ID | Scenario | Given | When | Then |
|-------|----------|-------|------|------|
| AC-003-01 | Happy path — duyệt hồ sơ | Admin xem chi tiết hồ sơ Companion đang ở trạng thái "Chờ duyệt" | Admin nhấn "Duyệt" | Trạng thái Companion chuyển thành "Đã duyệt"; hành động được ghi vào nhật ký kiểm toán; Companion nhận thông báo (nếu có) |
| AC-003-02 | Happy path — từ chối hồ sơ có lý do | Admin xem chi tiết hồ sơ Companion "Chờ duyệt" | Admin nhấn "Từ chối" và nhập lý do | Trạng thái Companion chuyển thành "Bị từ chối"; lý do được lưu; hành động được ghi nhật ký |
| AC-003-03 | Error — từ chối không có lý do | Admin xem hồ sơ Companion "Chờ duyệt" | Admin nhấn "Từ chối" mà không nhập lý do | Hệ thống yêu cầu Admin nhập lý do; không thực hiện từ chối |
| AC-003-04 | Edge — hồ sơ đã được xử lý bởi Admin khác | Admin A và Admin B cùng mở hồ sơ Companion X đang "Chờ duyệt" | Admin B duyệt trước; Admin A cũng nhấn "Duyệt" sau | Admin A nhận thông báo "Hồ sơ này đã được xử lý rồi"; trạng thái hiển thị cập nhật lại |
| AC-003-05 | Error — hồ sơ không ở trạng thái cho phép duyệt | Admin xem chi tiết Companion đã "Đã duyệt" | Admin cố gắng nhấn "Duyệt" lần nữa | Nút "Duyệt" không khả dụng hoặc hệ thống hiển thị "Không thể thực hiện hành động này với hồ sơ ở trạng thái hiện tại" |

### US-004: Khóa hoặc Mở Khóa Tài Khoản Companion

**As a** Admin, **I want** khóa hoặc mở khóa tài khoản Companion, **so that** tôi có thể xử lý kịp thời khi có vi phạm hoặc khôi phục tài khoản hợp lệ.

**Priority:** Must Have

#### Acceptance Criteria

| AC ID | Scenario | Given | When | Then |
|-------|----------|-------|------|------|
| AC-004-01 | Happy path — khóa tài khoản | Admin xem chi tiết Companion đang ở trạng thái "Đang hoạt động" | Admin nhấn "Khóa tài khoản" và xác nhận | Trạng thái Companion chuyển thành "Bị khóa" theo response của API; hành động được ghi nhật ký; FE cập nhật UI theo trạng thái mới |
| AC-004-02 | Happy path — mở khóa tài khoản | Admin xem chi tiết Companion đang "Bị khóa" | Admin nhấn "Mở khóa" và xác nhận | Trạng thái Companion chuyển thành "Đang hoạt động"; hành động được ghi nhật ký |
| AC-004-03 | Error — khóa tài khoản Companion đang có đặt lịch đang diễn ra | Companion có ít nhất 1 đặt lịch đang ở trạng thái "Đang thực hiện" | Admin nhấn "Khóa tài khoản" | Hệ thống cảnh báo "Companion này đang có buổi hẹn đang diễn ra. Bạn có chắc chắn muốn khóa?"; Admin phải xác nhận thêm lần nữa |
| AC-004-04 | Edge — khóa Companion đã bị khóa | Admin xem chi tiết Companion đang "Bị khóa" | Admin cố khóa lần nữa | Nút "Khóa" không khả dụng hoặc thông báo "Tài khoản này đã bị khóa rồi" |

| AC-005-03 | Error — không tìm thấy Client | Admin tìm kiếm tên không tồn tại | Admin nhập tên và thực hiện tìm kiếm | Hiển thị "Không tìm thấy Client nào phù hợp" |

**Priority:** Must Have

#### Acceptance Criteria

|-------|----------|-------|------|------|

| AC-007-02 | Happy path — tìm theo khoảng thời gian | Admin đang ở trang Quản lý Bookings | Admin chọn khoảng thời gian (từ ngày — đến ngày) | Danh sách chỉ hiển thị đặt lịch trong khoảng thời gian đó |

### US-008: Hủy Đặt Lịch Thủ Công

**As a** Admin, **I want** hủy đặt lịch thủ công, **so that** tôi can thiệp được trong các tình huống đặc biệt mà hệ thống không tự xử lý được.

**Priority:** Must Have

#### Acceptance Criteria

| AC ID | Scenario | Given | When | Then |
|-------|----------|-------|------|------|
| AC-008-01 | Happy path — hủy đặt lịch đang chờ xác nhận | Admin xem chi tiết đặt lịch đang "Chờ xác nhận" | Admin nhấn "Hủy đặt lịch" và nhập lý do | Trạng thái chuyển thành "Đã hủy"; lý do được lưu; Kanocoin được xử lý theo quy tắc hoàn tiền |
| AC-008-02 | Error — hủy đặt lịch không có lý do | Admin xem chi tiết đặt lịch đang chờ | Admin nhấn "Hủy" nhưng không nhập lý do | Hệ thống yêu cầu nhập lý do; không thực hiện hủy |
| AC-008-03 | Edge — hủy đặt lịch đã hoàn thành | Admin xem đặt lịch đã "Hoàn thành" | Admin cố nhấn "Hủy" | Nút "Hủy" không hiển thị hoặc không khả dụng; thông báo "Không thể hủy đặt lịch đã hoàn thành" |
| AC-008-04 | Edge — hủy đặt lịch đang diễn ra | Đặt lịch đang ở trạng thái "Đang thực hiện" | Admin nhấn "Hủy" | Hệ thống cảnh báo đây là buổi hẹn đang diễn ra và yêu cầu xác nhận thêm |

### US-009: Hoàn Tiền Kanocoin Cho Đặt Lịch

**As a** Admin, **I want** thực hiện hoàn tiền Kanocoin cho đặt lịch bị hủy hoặc tranh chấp, **so that** đảm bảo quyền lợi tài chính cho người dùng được xử lý minh bạch.

**Priority:** Must Have

#### Acceptance Criteria

| AC ID | Scenario | Given | When | Then |
|-------|----------|-------|------|------|
| AC-009-01 | Happy path — hoàn tiền toàn bộ cho Client | Admin xem chi tiết đặt lịch đã hủy hoặc tranh chấp | Admin chọn "Hoàn tiền toàn bộ cho Client" và xác nhận | Toàn bộ Kanocoin đã thanh toán được cộng lại vào ví Client; trạng thái đặt lịch cập nhật; hành động ghi nhật ký |
| AC-009-02 | Happy path — hoàn tiền một phần | Admin xem chi tiết đặt lịch tranh chấp | Admin chọn "Hoàn tiền một phần", nhập số Kanocoin cụ thể cho Client và Companion | Số Kanocoin tương ứng được phân phối cho từng bên; hành động ghi nhật ký |
| AC-009-03 | Error — số Kanocoin hoàn vượt quá số đã thanh toán | Admin nhập số Kanocoin hoàn | Tổng Kanocoin hoàn cho cả hai bên vượt quá số Kanocoin ban đầu của đặt lịch | Hệ thống hiển thị "Tổng Kanocoin hoàn vượt quá giá trị đặt lịch"; không thực hiện hoàn tiền |
| AC-009-04 | Edge — hoàn tiền cho đặt lịch đã hoàn tiền trước đó | Đặt lịch đã có trạng thái "Đã hoàn tiền" | Admin cố gắng hoàn tiền lần nữa | Hệ thống hiển thị "Đặt lịch này đã được hoàn tiền rồi"; nút hoàn tiền không khả dụng |

### US-011: Ra Quyết Định Xử Lý Tranh Chấp

**As a** Admin, **I want** ra quyết định xử lý tranh chấp (cho Client thắng, cho Companion thắng, hoặc bác đơn), **so that** tranh chấp được khép lại theo lựa chọn API hỗ trợ.

**Priority:** Must Have

#### Acceptance Criteria

| AC ID | Scenario | Given | When | Then |
|-------|----------|-------|------|------|
| AC-011-01 | Happy path — xử lý cho Client | Admin xem chi tiết tranh chấp đang "Mở" | Admin chọn "Xử lý cho Client" và nhập lý do | Toàn bộ Kanocoin hoàn về Client; tranh chấp chuyển trạng thái "Đã xử lý"; hành động ghi nhật ký |
| AC-011-02 | Happy path — xử lý cho Companion | Admin xem chi tiết tranh chấp đang "Mở" | Admin chọn "Xử lý cho Companion" và nhập lý do | Companion giữ toàn bộ Kanocoin; tranh chấp chuyển "Đã xử lý"; hành động ghi nhật ký |
| AC-011-03 | Happy path — bác đơn tranh chấp | Admin xem chi tiết tranh chấp đang "Mở" | Admin chọn "Bác đơn" và nhập lý do | Tranh chấp đóng với trạng thái bác đơn; Kanocoin giữ theo phân bổ ban đầu của booking; hành động ghi nhật ký |
| AC-011-04 | Error — ra quyết định không có lý do | Admin xem tranh chấp đang "Mở" | Admin chọn phương án xử lý nhưng không nhập lý do | Hệ thống yêu cầu nhập lý do quyết định; không thực hiện |
| AC-011-05 | Edge — tranh chấp đã được xử lý bởi Admin khác | Hai Admin cùng mở một tranh chấp; Admin A đã ra quyết định | Admin B cũng nhấn ra quyết định | Admin B nhận thông báo "Tranh chấp này đã được xử lý rồi"; hiển thị quyết định của Admin A |

## 5. Thỏa Thuận Làm Việc

### Giới Hạn Phạm Vi

> **Phạm vi FE + BFF only.** Spec này chỉ mô tả hành vi giao diện và luồng gọi API. Side-effect, business logic, notification, tính toán tỉ lệ, và quản lý trạng thái phía sau đều thuộc trách nhiệm của BE microservices. FE chỉ hiển thị đúng dữ liệu API trả về và gọi đúng endpoint khi người dùng thao tác.
